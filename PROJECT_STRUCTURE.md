# Project Structure

## Core Files

### Source Code
- **`main.ts`** - Main plugin file with Obsidian integration, settings UI, and font extraction
- **`converter.ts`** - Markdown to DOCX conversion logic, parsing, and formatting
- **`markdown-it-plugins.d.ts`** - TypeScript declarations for markdown-it plugins

### Configuration
- **`manifest.json`** - Plugin manifest (name, version, description)
- **`package.json`** - NPM dependencies and scripts
- **`tsconfig.json`** - TypeScript compiler configuration
- **`esbuild.config.mjs`** - Build configuration for bundling
- **`.eslintrc`** - Code linting rules

### Build Output
- **`main.js`** - Compiled plugin bundle (generated by build)
- **`styles.css`** - Plugin styles (if any)

## Documentation

- **`README.md`** - Main documentation (features, installation, usage)
- **`CHANGELOG.md`** - Version history and changes
- **`FEATURES.md`** - Detailed feature documentation
- **`DEVELOPMENT.md`** - Development guide
- **`INSTALL.md`** - Installation instructions
- **`WORD_LIMITATIONS.md`** - Explanation of Word format limitations
- **`LICENSE`** - MIT license

## Examples

- **`examples/FULL_MARKDOWN_SAMPLE.md`** - Comprehensive test of all features
- **`examples/TEST_ISSUES.md`** - Simple test file
- **`examples/SAMPLE.md`** - Basic example

## Dependencies

### Runtime
- `docx` - Word document generation
- `markdown-it` - Markdown parsing
- `markdown-it-emoji` - Emoji support
- `markdown-it-mark` - Highlight support
- `highlight.js` - Code syntax highlighting

### Development
- `@types/node` - Node.js type definitions
- `@types/markdown-it` - markdown-it type definitions
- `typescript` - TypeScript compiler
- `esbuild` - Fast bundler
- `builtin-modules` - Node.js built-in modules list

## Build Process

1. **TypeScript compilation** (`tsc -noEmit -skipLibCheck`)
   - Type checking only, no output
   - Validates all TypeScript code

2. **esbuild bundling** (`node esbuild.config.mjs`)
   - Bundles all code into `main.js`
   - Minifies for production
   - Handles external dependencies

## Development Workflow

```bash
# Install dependencies
npm install

# Development mode (watch for changes)
npm run dev

# Production build
npm run build

# Version bump
npm run version
```

## Key Design Decisions

### Why markdown-it?
- Robust, well-tested markdown parser
- Plugin ecosystem for emojis, highlights, etc.
- Handles edge cases better than regex-based parsing

### Why docx library?
- Pure JavaScript, works in browser and Node.js
- Comprehensive Word format support
- Active maintenance and good documentation

### Why esbuild?
- Extremely fast compilation
- Simple configuration
- Perfect for Obsidian plugins

### Font Handling
- Platform-specific fallbacks (Courier New for Windows, SF Mono for Mac)
- Validates font names to prevent "??" issues
- Supports Obsidian appearance matching

### Page Size Support
- Standard paper sizes (A4, A5, A3, Letter, Legal, Tabloid)
- Configurable via settings
- 1-inch margins on all sides
